# Auto2dLabel v0.3 里程碑定义

> v0.3 = 从检测分割到分类 OBB，从单图标注到批量闭环。

v0.3 状态：✅ 完成（2026-08 二次核查：分类 + OBB + Web 闭环补完 + M2/M3 Agentic 闭环全部落地；实测数据见 `tests/test-v0.3.md`）

> 2026-08-17 GPU 复测补记：RTX 4090 上全量 11 集 ~4 分钟跑通（CPU 需 30+ 分钟）；通用域 yolo26x 大胜（coco +0.20）；cityscapes 定性为**域边界**（COCO 预训练模型 30~50px 小目标定位极限，规模/SAHI/架构均无效，唯一出路域微调）；mot「反降」确认为 11-point AP 量化阶跃（非模型断崖）；coco_seg 瓶颈确认为 FastSAM 分割器（box-prompted SAM2 上限 **0.9278** vs FastSAM 0.4917）。详见 `tests/test-v0.3.md`「GPU 复测」。
>
> 2026-08-17 cityscapes 域内权重接入补记：域边界结论的「唯一出路」已落地——mmdet 官方 cityscapes Mask R-CNN 权重经一次性键名转换由 torchvision 纯本地推理（`maskrcnn_r50_cityscapes`，自检+分割一步到位），cityscapes val 全量 500 图 mask mAP@0.5 从 0.0082 提升至 **0.5149**（62.8×）。同时修复 GT instanceIds 解析既有 bug（`% 1000` → `// 1000`），此前 cityscapes 历史数字系坏 GT 下测得，仅作定性参考。详见 `tests/test-v0.3.md`「cityscapes 域内权重」。

## Phase 1: 图像分类 ✅

### 两条路线

| 路线 | 引擎 | 模型 | 说明 |
| --- | --- | --- | --- |
| 零样本 | transformers（懒加载，`HF_HOME=weights/hf`） | CLIP（`openai/clip-vit-base-patch32`）、SigLIP（`google/siglip-base-patch16-224`） | 多候选 softmax 排序取 top-K；中文候选可直接用 |
| 监督 | torchvision（`TORCH_HOME` 自动下载） | 14 款：convnext_large/base、maxvit_t、swin_b、efficientnet_v2_l、vit_b_16、resnet18/34/50/101/152、resnext50_32x4d/101_32x8d/101_64x4d | ImageNet1K 监督 top-K；candidates 子串过滤，**候选须英文**；resnet50 通用之选 |

### 使用

```bash
auto2dlabel chat "分类为猫和狗，用 clip" --no-wait              # 零样本（中文候选）
auto2dlabel chat "分类为 cat 和 dog，用 convnext_large" --no-wait  # 监督（候选须英文）
```

- 结果存 `Annotation.labels`（`list[ImageLabel]`），模型名存 `metadata["model"]`
- 导出：`export/cls.py`（cls 格式，round-trip 测试）

## Phase 2: OBB 旋转框检测 ✅

- **模型**：YOLO-OBB 15 款（yolo11/12/26 × n/s/m/l/x-obb.pt，DOTAv1 预训练）；Oriented R-CNN 延后（mmrotate 依赖重，取舍注记见计划书已知缺口）
- **角度约定（红线）**：`Bbox.angle` 弧度、(-π/2, π/2]、width 轴相对 x 轴（与 ultralytics xywhr 零转换）；穿透点四处（to_dict / state._annotation_from_dict / export._make_bbox / visualize）漏一处静默丢角
- **导出**：`export/dota.py`（dota / yolo_obb 两种格式）
- **评测**：`rotate_iou`（shapely 四边形求交）+ DOTA Task1 15 类全评（difficulty=1 按官方惯例剔除）；CPU 50 图实测 yolo11n-obb mAP@0.5 = **0.7047**，同场景 HBB 仅 0.0303（20× 差距，详见 `tests/test-v0.3.md`）

```bash
auto2dlabel chat "检测旋转框，用 yolo11n-obb.pt" --no-wait
```

## Phase 4: M2/M3 Agentic 闭环 ✅

### F4 代码级质量评估（`agent/evaluate.py`）

- `detect_with_retry()`：0 框 → 置信度 ×0.5 重试一次（每图最多一次）
- `evaluate_detections()` 纯函数：0 框 / 类别覆盖检查 / >200 框警告
- `QualityReport` 三通道输出：LLM `summary_line`（不含 >200 框警告，防 token 膨胀）/ metadata（`state.metadata["quality_report"]`）/ log
- 三条检测路径共用（Agent Loop / chat / no-LLM baseline）

### LLM Evaluate 节点（`tools/evaluate.py`）

- `evaluate_quality` **条件暴露**：仅当 `quality.ok == False` 时注入，不进全局 registry（防跨图污染）
- 动作：accept / flag_for_review / retry_lower_threshold（retry = conf×0.25，每图一次）；迭代核算 ≤3（Agent Loop 红线）

### 批量与主动学习

- batch 失败隔离 + `--resume outputs/batch_manifest.json`（跳过 ok，重跑 failed/pending）
- 主动学习采样 `auto2dlabel sample --top-k 5`（聚合 `outputs/*_review.json`）

## 同期追加：cityscapes 域内 Mask R-CNN ✅

- **动机**：cityscapes 检测步域边界（COCO 预训练模型对 30~50px 小目标 bbox mAP≈0）——两段式链路 full pipeline 基线 0.0082 失效
- **接入方式**：mmdet 官方 `mask_rcnn_r50_fpn_1x_cityscapes` 权重（Box 40.9 / Mask 36.4）→ 一次性键名转换（`tools/convert_mmdet_cityscapes_maskrcnn.py`）→ torchvision v1 结构纯本地推理，不引入 mmdet/mmcv
- **转换要点（两个框架语义差异坑）**：
  - 键名重映射：backbone→backbone.body、neck→backbone.fpn、rpn_head→rpn.head、bbox_head→box_predictor、mask_head→mask_head/mask_predictor
  - **背景位置**：mmdet fc_cls 为 (9,1024) 且背景在**最后一维**（label=num_classes）→ torchvision 背景在 index 0，需行重排 [fg×8, bg] → [bg, fg×8]（初版按「mmdet 不含背景」假设未重排，导致背景行被当作 bicycle，输出全 bicycle/1.0——IoU 分布验证 + 行重排修复）
  - 背景通道 padding：fc_reg 32→36、mask_fcn_logits 8→9 前置补零
- **推理尺度对齐**：`GeneralizedRCNNTransform(min_size=1024, max_size=2048)` 对齐 mmdet test_pipeline（2048×1024 keep_ratio + Pad 32 整除）
- **实测**（RTX 4090，500 图 110s / 4.5 img/s）：全量 val mask mAP@0.5 **0.5149** / mIoU 0.7552（基线 0.0082 → 62.8×），7 类全部检出；冒烟 2 图 0.7071
- **附带修复**：GT instanceIds 解析既有 bug（`inst_id % 1000` → `// 1000`，`cityscapes_benchmark.py`）——此前历史 cityscapes 数字系坏 GT 下测得

## 全量可视化 + chat 批量推理超参数（2026-08-17 追加）

**需求**：11 个 benchmark 数据集按对应任务全量推理并输出可视化（检测 bbox / 分割 mask / 分类 top-K / OBB 旋转框），产物镜像原相对路径保存到项目同级的 `Visualization/<数据集名>/`；chat 链路加入 `num_workers`/`batch_size` 两个超参数（CLI 显式 > 交互询问 > 按 GPU 显存自动推荐），批量推理尽可能用满 RTX 4090。

**实现要点**：
- `benchmarks/viz.py`：预测 dict 分派渲染（quad/mask/polygon/bbox/分类文本条），复用 `tools/visualize.py` 原语，断点续跑（已存在产物跳过）；`--viz` 接入全部 11 个脚本；`run_visualization.sh` 一键总入口
- chat 全链：`TaskStep` 加 `num_workers`/`batch_size` 字段（planner 仅在用户显式指定时提取）→ `cli.py` 参数 → `ask_with_timeout` 交互询问（非法重问 ≤3 次）→ `recommend_batch_params` 按 GPU 显存档位推荐（LLM prompt 注入与代码兜底同源：det/obb 8,4 / seg 4,4 / cls 16,4）
- 批量推理：单图协议（`detect`/`generate`/`classify`）签名冻结；各模型类加 `*_batch`（ultralytics `model(paths, batch=, workers=)` / torchvision list-of-tensors / CLIP 多图）；`cli_execute` 按 `batch_size` 分块 + `hasattr` 分派，SAM 系列与 SAHI 逐图回退；顺带修复 `_segmentation_step` 每图重建分割模型（提升到 step 级复用）

**d2sa OOM 修复（内存协议）**：D2SA 1920×1440 图 × 15654 实例，GT 全解码 mask 约 43GB + 预测 mask 43GB + 模型，超容器 cgroup 内存限制（62GB）→ 全量运行被 SIGKILL（退出码 137，实测）。修复：GT 存 COCO 原生 RLE（不解码）、预测存 polygon（SAM2 `Mask.segmentation` 原生压缩格式），评测时按类解码视图（`evaluate_mask_per_class` 协议不变，传入单类解码视图语义等价）——推理期内存 51GB → **2.5GB**。viz 增 polygon 分派（免解码直接填充）。注意：D2SA RLE counts 为特殊字符串编码，`pycocotools.mask.decode` 可解（annToMask 同路径），`frPyObjects` 不行。
