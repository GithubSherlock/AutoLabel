# Auto2dLabel v0.4 里程碑定义

> v0.4 = **3D 基石版**：为 Auto3dLabel 补齐 2D 支撑能力——Tracking（视频时序 ID）+ KITTI 域 2D 检测质量 + Agentic 骨架收尾。
>
> **战略定位（2026-08-19 调整）**：Auto2dLabel 的建立是为 Auto3dLabel 做基石。两个有关联的模块各有版本线：Auto2dLabel **优先交付能支撑 Auto3dLabel 的内容**（检测/分割/批量推理已就绪 → 本版补 Tracking/域内权重/骨架收尾）；此使命完成后才做与 3D 无关的内容（Pose 等 → v0.5+）。原「Pose 版」v0.4 定义作废，整体平移至 v0.5。

v0.4 状态：🔄 Phase 1 Tracking ✅ 完成（2026-08-19 ByteTrack 核心 + 2026-08-20 BoT-SORT 精度档 + 2026-08-21 chat 跟踪入口/TrackingTool 下沉，实测见 `auto2dlabel/tests/test-v0.4.md`）；Phase 2/3 📋 未动工。Phase 3 已于 2026-08-22 扩编：Agentic 骨架收尾 + **约束过滤层**（指代检测 L1 + 手动 ROI）+ Agent 运行模式完善（三方向整合定案见下）。与 auto3dlabel v0.1 单帧 MVP **双线并行**，排期见 `docs/AutoLabel_plan.md`「下一步」

## Phase 1: 视频 Tracking（ByteTrack/BoT-SORT）✅ 完成（2026-08-19）

- **ByteTrack 优先**：纯后处理（卡尔曼滤波 + 匈牙利匹配），零新增模型、轻量、实时——与「复用不引入重依赖」的 3D 路线同构；**BoT-SORT 精度档 ✅ 已实现（2026-08-20）**：`--bot-sort` 开关，ReID 外观关联（CLIP/SigLIP 图像编码器，复用 v0.3 分类的 transformers 懒加载基建）+ ECC 相机运动补偿，tools/ 跟踪算法本体保持零模型依赖（特征由调用方预提取注入）
- **范式选型（2026-08-19 讨论定案）**：tracking-by-detection 而非 box 级联合模型（MOTR/FairMOT 等）——本项目要的是「给现有检测框加 ID」（ID 是后加属性，盖在 29 模型/G-DINO 开放词汇的框上）；JDT 的 ID 焊死在其自产检测分支的框上，与 3D 管线（G-DINO+SAM2）消费的框无法对齐，开放词汇与 Phase 2 微调红利同样失效；JDT 精度并不落后（MOTRv3 79.4 ≈ ByteTrack 80.3），落选是架构约束而非精度偏好。联合路线对 3D 真正有价值的形态是视频级传播（SAM2 mask 传播/CoTracker3），已记入 auto3dlabel v0.1 增强候选
- 输入：视频帧序列 / 帧目录；检测步复用现成检测器（默认 `yolo26x.pt`，`--track` 开关）；跟踪器做 ID 维持
- 输出：逐帧 bbox + 全局 `track_id` + 轨迹；导出 MOT16/20 格式（`export/` 新格式，round-trip 测试）+ 可视化（ID 角标/轨迹线）
- **红线（评测口径）**：跟踪质量直接吃检测质量——mot 域差距（recall 0.1 量级）v0.3 已定性，评测必须**同时报 MOTA/IDF1 与检测 recall/IDSW**，避免「跟踪器背检测的锅」；低 recall 场景 mAP 横向对比教训（11-point 网格敏感）同样适用
- **3D 关联**：3D 标注最有价值的增量 = 跟踪 ID + 运动属性（速度/加速度）——Auto3dLabel v0.2 多帧直接依赖本 Phase 的 ID 维持能力

### 3a. 约束过滤层 + 指代检测 L1 + 手动 ROI（2026-08-22 讨论定案，方向 B∩C）

**统一洞察**：「穿红衣服的人」（属性）、「车道上的行人」（空间 ROI）、「左边的人」（方位）本质是同一件事——**类别之外的附加约束**。统一为一条过滤链，B 的执行层与 C 的空间约束复用同一实现：

```
指令 → planner/文本 LLM 解析为结构化约束 {class, attributes[], spatial}
     → 检测类别框（现有 29 模型）→ 约束过滤层
     → 属性过滤：CLIP 逐框零样本分类（复用 v0.3 分类基建，零新权重，单框几十 ms）
     → 空间过滤：ROI 多边形 / 方位词代码级过滤（左/中/右/前/后 → 坐标分位）
     → 剩余目标 → 跟踪/标注（TrackingTool/DetectionTool 检测后处理挂接，纯函数可单测）
```

- **B（指代检测）分层定案**：L1（文本解析 + CLIP 属性过滤 + 代码级方位）= 本 Phase，零新权重、CPU 可测——覆盖「类别+可枚举属性+简单方位」这一 80% 场景；L2 Florence-2（~1-2.4G，复杂指代 CPU 低频兜底）/ L3 Qwen2-VL（~4.5G，需 GPU）→ 延后表
- **C（定制化检测）两级定案**：C1 手动 ROI（多边形/矩形）= 空间约束的一种输入方式，零新依赖，本 Phase 先做；C2 自动车道 ROI（VLM 看图生成车道多边形或车道线模型）→ 延后表，复用同一空间过滤实现
- 解析产物：`resolve_plan` 返回 `(prompts, threshold)` 升级为结构化约束对象（无约束时向后兼容退化为纯 prompts）
- 测试：合成框 + Fake CLIP 零真实权重单测（沿用 ReID 铁律）；方位/ROI 过滤纯函数直接断言
- **3D 关联**：「自车前方区域」ROI 是 3D 标注通用能力，约束过滤层一次建设双线复用

### 3b. Agent 运行模式完善（2026-08-22 讨论定案，方向 A）

现状 Agent Loop 已极克制（max_iterations=3 / detect 仅一次 / LLM Evaluate 条件暴露且代码执行），补两档能力，**纯编排改动零新模型**：

- **模型级重试**：质量不合格时除「降阈值重试」外，新增 LLM 决策「换模型重跑一次」（yolo 漏检 → G-DINO/fasterrcnn，或检测→分割）——把 29 模型库真正交给 agent 编排；代码级防循环（每图一次）
- **批次/序列级策略**：LLM 先看整批抽样统计（逐图框数/缺类率汇总）定调参策略，逐图走 no-LLM 代码级执行——LLM 成本从「每图一次」降到「每批一次」
- 3D 关联：Auto3dLabel 复用 Agentic 骨架时直接继承
