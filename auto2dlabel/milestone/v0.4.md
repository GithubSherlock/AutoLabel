# Auto2dLabel v0.4 里程碑定义

> v0.4 = **3D 基石版**：为 Auto3dLabel 补齐 2D 支撑能力——Tracking（视频时序 ID）+ KITTI 域 2D 检测质量 + Agentic 骨架收尾。
>
> **战略定位（2026-08-19 调整）**：Auto2dLabel 的建立是为 Auto3dLabel 做基石。两个有关联的模块各有版本线：Auto2dLabel **优先交付能支撑 Auto3dLabel 的内容**（检测/分割/批量推理已就绪 → 本版补 Tracking/域内权重/骨架收尾）；此使命完成后才做与 3D 无关的内容（Pose 等 → v0.5+）。原「Pose 版」v0.4 定义作废，整体平移至 v0.5。

v0.4 状态：🔄 Phase 1 Tracking ✅ 完成（2026-08-19 ByteTrack 核心 + 2026-08-20 BoT-SORT 精度档，实测见 `auto2dlabel/tests/test-v0.4.md`）；Phase 2/3 📋 未动工。与 auto3dlabel v0.1 单帧 MVP **双线并行**，排期见 `docs/AutoLabel_plan.md`「下一步」

## Phase 1: 视频 Tracking（ByteTrack/BoT-SORT）✅ 完成（2026-08-19）

- **ByteTrack 优先**：纯后处理（卡尔曼滤波 + 匈牙利匹配），零新增模型、轻量、实时——与「复用不引入重依赖」的 3D 路线同构；**BoT-SORT 精度档 ✅ 已实现（2026-08-20）**：`--bot-sort` 开关，ReID 外观关联（CLIP/SigLIP 图像编码器，复用 v0.3 分类的 transformers 懒加载基建）+ ECC 相机运动补偿，tools/ 跟踪算法本体保持零模型依赖（特征由调用方预提取注入）
- **范式选型（2026-08-19 讨论定案）**：tracking-by-detection 而非 box 级联合模型（MOTR/FairMOT 等）——本项目要的是「给现有检测框加 ID」（ID 是后加属性，盖在 29 模型/G-DINO 开放词汇的框上）；JDT 的 ID 焊死在其自产检测分支的框上，与 3D 管线（G-DINO+SAM2）消费的框无法对齐，开放词汇与 Phase 2 微调红利同样失效；JDT 精度并不落后（MOTRv3 79.4 ≈ ByteTrack 80.3），落选是架构约束而非精度偏好。联合路线对 3D 真正有价值的形态是视频级传播（SAM2 mask 传播/CoTracker3），已记入 auto3dlabel v0.1 增强候选
- 输入：视频帧序列 / 帧目录；检测步复用现成检测器（默认 `yolo26x.pt`，`--track` 开关）；跟踪器做 ID 维持
- 输出：逐帧 bbox + 全局 `track_id` + 轨迹；导出 MOT16/20 格式（`export/` 新格式，round-trip 测试）+ 可视化（ID 角标/轨迹线）
- **红线（评测口径）**：跟踪质量直接吃检测质量——mot 域差距（recall 0.1 量级）v0.3 已定性，评测必须**同时报 MOTA/IDF1 与检测 recall/IDSW**，避免「跟踪器背检测的锅」；低 recall 场景 mAP 横向对比教训（11-point 网格敏感）同样适用
- **3D 关联**：3D 标注最有价值的增量 = 跟踪 ID + 运动属性（速度/加速度）——Auto3dLabel v0.2 多帧直接依赖本 Phase 的 ID 维持能力

| GT-as-detection 上界模式（2026-08-19 追加） | `mot_tracking_benchmark.py --gt-as-detection` | 检测=GT（conf=1.0 直喂 ByteTracker，跳过检测）评测跟踪关联上界——FN/FP 结构性为零，MOTA 损失唯一来源 IDSW；与真实管线对比定量分离「检测的锅/跟踪的锅」（实测 MOT17-02 20 帧上界 MOTA/IDF1=1.0 vs 真实 12.7%）；未来 tracker 参数调优的对照基线；测试 `test_gt_as_detection.py` 2 用例（理想场景 1.0 + 遮挡恢复零 IDSW） |
| 纯 tracker 耗时微基准（2026-08-19 追加） | `benchmarks/tracker_time_benchmark.py` | 合成随机游走检测（确定性 seed，10% 遮挡 + 高低分两段关联激活）直喂 tracker，密度扫 10-200 框/帧——隔离匈牙利 O(n³) 后处理成本（实测 200 框/帧 124ms/帧，相对检测可忽略）；测试 `test_tracker_time_benchmark.py` 4 用例（生成器确定性 + 场景语义 + 计时形状） |

| BoT-SORT 精度档（2026-08-20 追加） | `models/tracking.py BotSORTTracker` | ByteTracker 子类（本体不动）：第一段融合 cost λ·(1−cos)+(1−λ)·(1−IoU)（λ=0.98）+ cosine 门控 0.25（任一侧缺特征回退纯 IoU 通道）；特征 EMA α=0.9 + L2 重归一化（低分救援不更新）；ECC 相机运动补偿（cv2.findTransformECC 作用于轨迹预测框，仅高分段，下采样 cmc_max_side=640 + 合理性三查退化回退）；官方默认 track_high_thresh 0.6 / new_track_thresh 0.7（ByteTracker 仍 0.5/0.5） |

| CLI/benchmark 接线（2026-08-20 追加） | `cli.py --bot-sort/--reid-model` + `mot_tracking_benchmark.py` | run/benchmark 双入口透传；PIL 打开失败/特征缺失自动降级纯 ByteTrack 语义；benchmark tracker 名字符串随模式（产物文件区分 `-botsort` 后缀）；对比红线：同序列同窗口同 conf（BoT-SORT 用官方 0.6/0.7 轨迹阈值，检测 conf 不变） |
| BoT-SORT 单测（2026-08-20 追加） | `test_bot_sort.py` + `test_reid_model.py` | 18 + 12 用例：扩展关断时与 ByteTracker 逐位相等（最强无回归锚点）、swap 场景数学构造证明 ReID 门控阻止纯 IoU 匈牙利交换、特征 EMA 精确值、ECC 平移/旋转恢复 + 退化回退 + 合理性三查、确定性 property（含 ECC 开） |
