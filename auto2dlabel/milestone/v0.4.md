# Auto2dLabel v0.4 里程碑定义

> v0.4 = **3D 基石版**：为 Auto3dLabel 补齐 2D 支撑能力——Tracking（视频时序 ID）+ KITTI 域 2D 检测质量 + Agentic 骨架收尾。
>
> **战略定位（2026-08-19 调整）**：Auto2dLabel 的建立是为 Auto3dLabel 做基石。两个有关联的模块各有版本线：Auto2dLabel **优先交付能支撑 Auto3dLabel 的内容**（检测/分割/批量推理已就绪 → 本版补 Tracking/域内权重/骨架收尾）；此使命完成后才做与 3D 无关的内容（Pose 等 → v0.5+）。原「Pose 版」v0.4 定义作废，整体平移至 v0.5。

v0.4 状态：📋 未动工（2026-08-19 立项；与 auto3dlabel v0.1 单帧 MVP **双线并行**，排期见 `docs/AutoLabel_plan.md`「下一步」）

---

## Phase 1: 视频 Tracking（ByteTrack/BoT-SORT）📋

- **ByteTrack 优先**：纯后处理（卡尔曼滤波 + 匈牙利匹配），零新增模型、轻量、实时——与「复用不引入重依赖」的 3D 路线同构；**BoT-SORT**（+REID 特征，需额外 embedder 模型）备选精度档
- 输入：视频帧序列 / 帧目录；检测步复用现成检测器（默认 `yolo26x.pt`，`--track` 开关）；跟踪器做 ID 维持
- 输出：逐帧 bbox + 全局 `track_id` + 轨迹；导出 MOT16/20 格式（`export/` 新格式，round-trip 测试）+ 可视化（ID 角标/轨迹线）
- **红线（评测口径）**：跟踪质量直接吃检测质量——mot 域差距（recall 0.1 量级）v0.3 已定性，评测必须**同时报 MOTA/IDF1 与检测 recall/IDSW**，避免「跟踪器背检测的锅」；低 recall 场景 mAP 横向对比教训（11-point 网格敏感）同样适用
- **3D 关联**：3D 标注最有价值的增量 = 跟踪 ID + 运动属性（速度/加速度）——Auto3dLabel v0.2 多帧直接依赖本 Phase 的 ID 维持能力

## Phase 2: KITTI/自动驾驶域 2D 检测质量 📋

- **KITTI object benchmark 接入 2D 评测**：`image_2` + `label_2` GT 已就位（`Documents/datasets/KITTI/object`，2026-08-19 从 `/autodl-pub/data/KITTI/object` 补齐 velodyne/calib/image_2 全量）；2D bbox AP 按 **difficulty 分层**（easy/moderate/hard，沿用 DOTA difficulty 剔除经验）
- 现有权重 KITTI 域基线：v0.3 GPU 复测 0.4081（yolo26x）/ CPU nano 0.2610——域差距中等，可产出「预标 + HITL 修正」的可用初稿
- **域内微调权重**（GPU 到位后）：KITTI 2D 检测微调，cityscapes 0.0082→0.5149 先例闭环——预标注 → 微调 → 回采
- **3D 关联**：2D 检测失效 → 3D 必失效；3D bbox 初稿质量的上限由本 Phase 决定

## Phase 3: Agentic 骨架收尾 📋

- **AgentState from_dict 恢复**（to_dict 快照已写，恢复未实现）——Auto3dLabel 复用 Agentic 编排（planner/orchestrator/HITL）骨架的前提
- 其余低成本缺口视排期顺手消化（Web 分类/OBB 展示、bbox 拖拽编辑）
