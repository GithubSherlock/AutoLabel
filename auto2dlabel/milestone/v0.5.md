## 规划内容

### 1. Pose 姿态估计

- ViTPose/RTMPose + COCO keypoints 导出（关键点挂 bbox 数据流，YOLO-pose 可先行）
- 原 v0.4「Pose 版」定义整体平移至此；与 3D 无依赖，殿后

### 2. 指代检测 L2（Florence-2 兜底）

- **触发**：v0.4 约束过滤层 L1（文本解析 + CLIP 属性 + 代码方位）解析不出/过滤失败时兜底——关系/复合指代（「红车旁边的行人」「第二辆车后面的人」）
- **形态**：Florence-2-base 0.23B（~1G）/ large 0.77B（~2.4G），任务词条架构（非聊天模型，微软统一视觉基础模型）
- **成本**：CPU 单图 5-30s——低频使用（序列级一次指代识别），不做逐帧
- **架构**：插入 v0.4 3a 过滤链的「属性/关系判断」环节，输出结构化约束或直接出框

### 3. 指代检测 L3（Qwen2-VL-7B）

- 复杂上下文指代（「第二辆车后面穿红衣服的人」）——L2 也覆盖不了的复合场景
- Q4 量化 ~4.5G 权重；CPU 分钟级不可用 → **GPU 到位后**低频关键帧（视频序列级一次指代识别）
- 与 L2 的关系：同一调用点，按能力/成本阶梯升级

### 4. 自动车道 ROI（v0.4 C2）

- 车道线模型（YOLOP/Ultra-Fast-LODA）或 VLM 看图生成车道多边形 → 空间约束自动输入
- **复用 v0.4 3a 空间过滤实现**（ROI 多边形是输入方式差异，过滤链零改动）
- 依赖 v0.4 约束过滤层先落地

### 5. 分类数据集扩展

- ILSVRC2012 val 接入（ImageNet100 已闭环）

### 6. Web 交互增强

- bbox 拖拽/标签编辑、分类与 OBB 展示（如未在 v0.4 Phase 3 消化）
