# Auto2dLabel v0.6 里程碑定义

> v0.6 = **对话式 Agent 统一入口**：`chat "<指令>"` 成为唯一入口，LLM 与用户多轮对话确定全部参数 → 执行。
> 立项 2026-08-28（用户决策：架构迭代优先——chat 唯一入口 + 智能对话确定参数；auto3dlabel v0.3 的 P1-P4 相应顺延）。

## 背景与决策

现状两入口：`run`（Agent Loop，每图 LLM tool-use 循环）+ `chat`（Planner 单轮 JSON 解析 → 纯代码执行，缺参靠代码级 `ask_with_timeout` 追问）。用户目标：**只接受 `chat "..."` 即可输出**，参数通过 LLM 驱动对话确定（而非固定规则追问）。

技术判断（2026-08-28 论证）：
- **对话式参数确定：值得做**——Planner 从「单轮 JSON 解析 + 代码级追问」升级为「LLM 驱动多轮对话收集」，TaskPlan schema 不变、execute_plan 零改动，成本上限可控
- **多 agent 编排框架（LangGraph/AutoGen/CrewAI 等）：不引入**——本项目 LLM 决策点仅 3 处（规划/质量处置/调参）且条件触发；质量防线在 F4 代码层 + HITL，比 agent 间辩论更可靠更便宜；多 agent 放大唯一外部依赖（DeepSeek）失败面，违背「无 key 零影响」红线

三项锁定决策：
1. **范围**：`parse_dialog` 多轮对话 + `--no-wait` 降级保留 + 通用对话骨架 2D/3D 共用 + 远期 run 并入 chat
2. **形态**：对话循环通用化（auto2dlabel/agent/dialog.py），2D/3D planner 各自提供 prompt + schema（复用不复制）
3. **run 保留**（v0.6 阶段）：Agent Loop 是「LLM 在环处置」唯一形态（evaluate_quality 条件暴露），chat 检测步暂不升级为 Agent Loop；**远期目标**：chat `--agentic` 开关吸收 run，run 命令降级为别名

## Phase 1：对话式 Planner（parse_dialog）📋

### 设计：多轮对话收集

```
chat "检测视频里穿红衣服的人并跟踪"          （无 --no-wait）
  → 第 1 轮：LLM 解析 → JSON + questions[]
     {
       "steps": [{"task_type":"tracking","source":"","prompts":["person"],...}],
       "confirm_timeout": 30,
       "questions": [
         {"id": "step1.source", "question": "视频/图像目录在哪里？"},
         {"id": "step1.prompts", "question": "要跟踪哪些类别？(如 person, car)"}
       ]
     }
  → 代码层一次渲染全部问题（复用 ask_with_timeout 超时交互，自由文本回答）
  → 回喂用户回答 → 第 2 轮 LLM 更新 TaskPlan
  → questions 为空 → 确认 → execute_plan（零改动）
```

### 关键机制

- **JSON schema 扩展**：`questions: [{id, question}]`——id 定位到 `step{id}.{field}`，代码只校验字段存在性，**参数提取仍由 LLM 完成**（自由文本回答喂回 LLM）
- **轮次上限 = 3**（对齐 Agent Loop `max_iterations=3` 红线）；耗尽后走代码兜底补缺（现状 `ask_missing_params` 保留）
- **降级链**：LLM 响应非法 / questions 解析失败 / 无 key → 现有单轮 `parse` + 代码兜底，零行为回退
- **`--no-wait`（timeout=0）**：跳过对话轮，直接代码兜底（现状行为不变）
- **成本**：每轮 1 次 LLM 调用，最多 3 轮；`temperature=0`；prompt 注入 GPU 上下文与模型目录（沿用现有 `_gpu_context_line` + `format_catalog_summary`）
- **通用骨架**：`agent/dialog.py` 提供 `parse_with_dialog(llm, system_prompt, parse_fn, ask_fn, max_rounds=3)`——渲染问题/收集回答/回喂/轮次控制与 schema 无关；2D/3D 各自注入（复用不复制红线）

### 验收

| 项 | 验收 |
| --- | --- |
| 对话闭环 | `chat "检测视频里穿红衣服的人并跟踪"`（无 --no-wait）→ 对话问出 source/prompts → 执行 → 输出 |
| 完整指令零对话 | `chat "检测 /data/images 中的汽车" --no-wait` → 无 questions → 直接执行（行为与 v0.5 一致） |
| 轮次上限 | mock LLM 恒返回 questions → 3 轮后代码兜底执行 |
| 非法响应降级 | mock 非法 JSON / questions 字段缺失 → 降级单轮 parse 成功 |
| 无 key 零影响 | 无 API key → 走代码兜底全默认参数 |
| 3D 贯通 | auto3dlabel chat 同机制（见 auto3dlabel v0.3 P1） |

## Phase 2：类别推荐并入对话（可选，视 Phase 1 落地形态）📋

- `_maybe_recommend_classes`（代码级类别推荐）保留；对话轮 questions 不再涉及类别推荐（推荐是模型类别表知识，代码级更准）
- 若对话中用户表达「不知道标什么类别」→ LLM 在 questions 中表达 → 代码推荐类别后回喂用户确认

## 远期（v0.6 后，不承诺）

- chat `--agentic`：检测步可选升级为 Agent Loop（吸收 run 的 LLM 在环处置能力）；run 命令降级为 `chat --agentic` 别名
- 多 agent 研究决策模式：一次性多视角评审（同一问题 2-3 个独立 LLM 调用投票，用完即弃）——留给研究型任务（如 LabelAny3D 复现结论）
