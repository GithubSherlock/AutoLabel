# Auto3dLabel v0.1 里程碑定义

> v0.1 = 3D 标注 MVP：单帧点云 + 相机图像 → 2D 基础模型 → 3D bbox 初稿（路线 2「2D → 3D 提升」）。面向物理 AI / 自动驾驶：3D bbox 是自动驾驶标注价值栈的第一层（→ 跟踪 ID/运动属性 → BEV/占用 → HD 地图）。

v0.1 状态：✅ **已完成（2026-08-24）**——五步管线 + Agentic 闭环 + Web 复核 + 128 用例 + 质量门全绿。实测数据见 `../tests/test-v0.1.md`；实现速查见 `../CLAUDE.md`。范围调整：**v0.1 仅 KITTI**（nuScenes 延后 v0.2）；2026-08-17 立项、2026-08-19 战略调整为主推进。调研与路线论证见 `docs/AutoLabel_plan.md` Auto3dLabel 部分

> **核心决策**：MVP 复用 Auto2dLabel 已交付的 G-DINO + SAM2 2D 能力与 Agentic/HITL 骨架，**零新增模型**；新增代码只有「点云加载 → 反投影 → 聚类 → bbox 拟合 → 导出」五步。不引入 3D 检测模型（路线 1 依赖），不碰 3DGS（路线 3，远期）。

> **数据已就位（2026-08-19）**：KITTI object（3D 检测基准，正确版本）位于 `Documents/datasets/KITTI/object`——原目录仅 image_2 部分 + label_2 全量，已从 `/autodl-pub/data/KITTI/object` 补齐 velodyne（点云）/calib（标定）/image_2 全量 7481 训练帧 + testing。

> **版本路线（显式化）**：v0.1 单帧 3D bbox → v0.2 多帧 + 跟踪 ID/运动属性（依赖 Auto2dLabel v0.4 Tracking）→ v0.3+ BEV/占用与重建路线评估。每一版都有自动驾驶价值增量。

> **多帧增强候选（2026-08-19 讨论定案）**：v0.2 的 mask 跨帧传播候选——**SAM2 视频传播**（首帧 G-DINO+SAM2 prompt → 后续帧 mask 传播，权重已在 84 模型目录，零新增，免逐帧重跑）/ **CoTracker3 点跟踪**（车载运动对应强，新权重，仅调研）；box 级 JDT（MOTR 等）**不入选**：其 ID 焊死在自己检测分支的框上，与 3D 管线消费的 G-DINO 框无法对齐（选型论证见 `auto2dlabel/milestone/v0.4.md` Phase 1）。

> **3D 检测模型演进路径（2026-08-23 调研）**：LiDAR 系是唯一可达标注业务精度的路线（KITTI car moderate AP3D 74–81：SECOND 78.2 / PointPillars 77.6 / PV-RCNN 81.4，OpenPCDet+MMDet3D 双框架权重齐全，12GB 可跑、秒级单帧）；单目系 moderate ≤30% 只配兜底；无 ultralytics 式 3D 全家桶。反投影拟合有精度天花板（长距/遮挡/粘连退化）——预标注不达标时的演进方向是引入 **CenterPoint/PointPillars（用 MMDet3D 完整权重，避开 OpenPCDet underfit demo 权重）**，而非无限调聚类参数。CVAT 参考 + 候选清单详见 `auto3dlabel/CLAUDE.md`。

## Phase 1: 数据与标定加载 ✅

- **KITTI**：velodyne `.bin`（x,y,z,intensity）×4 float32 + `calib_*.txt`（P2 / R0_rect / Tr_velo_to_cam 投影链）
- **nuScenes**：延后 v0.2（v0.1 范围调整，只做 KITTI）
- 内部统一：点云存 LiDAR 系；相机内参 K + 外参 T 组成投影链（点云 → 图像）
- **红线**：标定链任何一环错 → 投影全错且难察觉；必须做「点云投影回图像散点图」自检 ✅（26/27 GT 框双重验证，见 test-v0.1.md）

## Phase 2: 2D mask → 语义点云 ✅

- 复用 auto2dlabel：G-DINO 开放词汇 bbox（或 YOLO 检测）→ SAM2 box-prompt mask；分类标签随 mask 传递
- 反投影：图像 mask 内的 LiDAR 点 = 该类别语义点云（只取 LiDAR 实际观测到的点）✅（rasterize 查表一次矩阵乘 + 花式索引，115k 点毫秒级）
- 多相机融合：v0.1 单相机（KITTI 左彩色相机）
- **红线**：反投影用 **mask 不用 bbox** ✅

## Phase 3: 聚类 + 3D bbox 拟合 ✅

- DBSCAN 实例聚类（sklearn，eps 按类别：Car 1.0 / Pedestrian 0.5 / Cyclist 0.7，configs 单一事实源；>2 万点先 0.1m 体素降采样）
- 鸟瞰 xz `cv2.minAreaRect` → **角点法 yaw**（boxPoints → 最长边方向，绕开 cv2 4.x angle 字段语义坑）+ z 5–95 分位高度
- **rotation_y 转换（唯一转换点，官方约定独立推导验证）**：`rotation_y = yaw_bev − π/2`；180° 模糊 → IoU 不受影响 + review_flag
- **红线**：拟合点数 fit_points 量化置信度 → <MIN_FIT_POINTS(20) 强制 review（宁缺勿假）✅

## Phase 4: 导出 + 评测 + 闭环 ✅

- **导出**：KITTI label 15 字段（类映射 COCO→KITTI，y 底部中心回写，rotation_y 相机系）
- **评测**：双层 benchmark——BEV 层（"quad" 8 值）+ 3D 层（"bbox" 7 值，iou_fn 注入 `evaluate_per_class`）+ KITTI difficulty 分层；⚠️ 3D 层 quad 优先污染 bug 已修（见 test-v0.1.md）
- **HITL**：triage_3d 三档（conf 三档 + fit_points<20/review_flag 强制 review）+ `*_review.json`（加 pcd_path/calib_path/bev_path，3D 字段直通）
- **Agentic**：`auto3dlabel chat` 全闭环 ✅（planner3d → 3D registry → orchestrator 复用循环 → fit_points 判据 → HITL 导出）；**Web 复核**：四端点协议 + 3D save（删框/编辑 → KITTI label 回写），前端简版（相机图 + BEV 图 + 列表操作，无点云上传）

## 模型/依赖汇总（v0.1）

- **模型零新增**：复用 auto2dlabel 84 模型目录（G-DINO + SAM2/SAM3 + YOLO）
- **新增依赖**：scikit-learn（DBSCAN，唯一新增，已装）；cv2（渲染/栅格化）、shapely（BEV IoU）、numpy 均为环境已有
- **数据**：KITTI object 全量就位（training 7481 + testing 7518）；nuScenes 延后 v0.2（数据与权重不入库，同 2D 红线）
- **CLI**：`auto3dlabel run 000123 "检测汽车" -d yolo11s_kitti`（直跑）/ `auto3dlabel chat "标注 KITTI 帧 000123 中的汽车"`（LLM 闭环）；批量 + resume 失败隔离
