# Auto3dLabel v0.4 里程碑定义

> v0.4 = **HITL 编辑闭环补齐（P1 手柄编辑，最高优先）** + nuScenes 端到端标注闭环（P2）+ 训练→微调闭环（P3，v1.0 方向，成本高可延后）。
> 立项 2026-08-31（v0.3 收尾评估：3D 核心闭环已完整，剩余为增量项——用户采纳评估建议，三项候选入 v0.4）。

## 背景与决策

v0.3 收尾（2026-08-31）后现状：检测模型矩阵 9 引擎（LiDAR 5 + 单目 2 + 融合 2，KITTI/nuScenes 双数据集）+ HITL 三档分流 + Web 真 3D 四视图复核 + Agentic 闭环 + 多格式导出——**核心闭环完整，无「必须马上做」项**。v0.4 沿价值栈补齐三块增量：

1. **P1（推荐优先）**：P4b 手柄编辑——v0.3 明确记录「可选未做」的唯一规划项；补齐后「AI 初稿 → 人工修正」数据回路在 3D 侧真正完整（当前人工只能改标签、不能改 cuboid 几何）
2. **P2**：nuScenes 端到端标注闭环——BEVFusion / centerpoint / fcos3d 目前只评测出表，「测了不能用」；nuScenes pcd Web 复核无解析器（v0.1 记缺口至今未补）
3. **P3**：训练→微调闭环——标注数据反哺模型（auto2dlabel 侧 `tools/train_kitti.py` 先例），mmdet3d 微调域内再训练；成本最高，可延后

## Phase 1：P4b cuboid 手柄编辑（Web 3D 复核补齐）

- **定位**：v0.3 P4a 已交付只读四视图 + 选中/改标签/删除/保存回写；**cuboid 几何编辑缺失**——AI 初稿框不准时人工无法修正尺寸/位置/yaw，只能改标签或重跑引擎
- **范围**（纯前端，three.js 已就位，不占 GPU）：
  - **cuboid 六面拖拽手柄**：六面中心手柄拖拽改对应面、角点吸附 raycast 模板（CVAT 借鉴）；编辑数学照 `resize/rotate` 既有模式（手柄相对 mousedown 快照，绝不增量累积）
  - **编辑对象**：尺寸 h/w/l、位置 xyz、yaw（BEV 平面旋转）——内部数据模型 `{position, size, yaw}` 不变
  - **保存回写**：Box3D `to_dict` 穿透点纪律（v0.1 红线，新增编辑路径不得绕过）；`*_reviewed.json` 协议扩展或原地覆盖（照 2D 协议）
  - **撤销/重做**：沿用 undo/redo 闭包栈模式（MAX 32，快照深拷贝）
- **验收**：
  - Web 打开 KITTI 帧 → 拖拽手柄修改 cuboid（尺寸/位置/yaw）→ 保存 → 导出 label 校验（15 字段 h/w/l/x/y/z/ry 与编辑一致）
  - jsdom 冒烟覆盖手柄数学（照 `smoke_web.js` 模式：mousedown 快照、六面拖拽、yaw 旋转、undo/redo）
  - 与 2D Web 复核（:8765）同端口共存回归（test_web3d 全绿）
- **成本**：1000+ 行 JS（v0.3 评估最重前端单块）；不做 raycast 模板吸附可降级为六面手柄 MVP

### Phase 1 验收回填（2026-08-31 ✅）

- **交付**：logic3d.js 编辑层（boxToCorners / yaw↔rotation_y 转换 / 2D 母版 resize 适配 + 增量式 yaw 旋转 + Side 一维编辑 / 状态机 + undo 闭包栈 MAX 32）+ viewer3d.js 手柄层（Top 4 角 + 4 边 + yaw 球、Side 顶/底/前/后，投影命中 <14px，中心平面射线求交拖拽，编辑中禁用视图旋转、实时几何刷新、相机锁定）+ index.html 编辑 hint。**后端零改动**（编辑体操作队列 JSON annotations[i]，buildSaveBody 全量直通）
- **验收对照**：六面手柄覆盖 ✓（Top BEV 面 + Side 立面六面）；尺寸/位置/yaw 全可编辑 ✓（w/l/位置 Top、h/cy Side、l/cz Side、yaw Top 球）；保存回写 + 导出走既有链路 ✓（编辑后 save → server 3D from_dict → labels/ 导出，穿透点纪律保持）；jsdom 冒烟 ✓（smoke_web3d.js 94 断言，编辑层 33）；同端口共存回归 ✓（pytest 双环境全绿，后端零改动）
- **MVP 降级如实记录**：raycast 模板吸附、Front/透视视图手柄不实现（覆盖重复）；undo 不覆盖删除/改标签（P4a 现状保持）；容器无浏览器可自动化 → 拖拽 E2E 手动验收待用户（数学/状态机/undo 由 smoke 断言兜底）
- **过程修正两处**：`edited_by_human` 置位时机（endEdit 几何容差判定，零变化不假标记、浮点往返噪声清理由 snapshot 恢复）；P4a 遗留 click 拦截失效修复（suppressClickUntil 时间戳）
- 实测数据见 `tests/test-v0.4.md`；质量门四件套全绿（pytest 1056/4 + 1059/1、ruff 0/75、mypy 0/167、pyright 0）

## Phase 2：nuScenes 端到端标注闭环

- **定位**：BEVFusion（mAP 27.0）/ centerpoint（23.4）/ fcos3d 均为评测出表，无标注闭环——nuScenes sample 无法 Web 复核、无训练格式导出，「融合/单目引擎主推但不可用」是价值兑现缺口
- **范围**：
  - **nuScenes pcd 解析渲染**：Web 复核第 6 相机 + LIDAR_TOP 点云（pcd 无解析器为 v0.1 记缺口；复用 `data/nuscenes.py` devkit 表 + `build_bevfusion_data` 标定链）
  - **复核队列协议扩展**：review 文件加 nuScenes sample 语义（scene/sample token 定位，非 frame_id）
  - **nuScenes 训练标签导出**：devkit 格式（bbox + 全局四元数 + 类别表），与 `export/` 现有 KITTI 导出并列
- **验收**：Web 复核 nuScenes sample（点云 + 6 相机 + 3D bbox 四视图）→ 改标签/保存 → devkit 可读标签导出 → 回灌评测口径可解析
- **成本**：中等（pcd 解析 + 前端相机视图 + 导出器）；nuScenes Web 复核无现成解析器，前端工作量同 P1 量级

## Phase 3：训练→微调闭环（v1.0 方向，成本高可延后）

- **定位**：标注数据反哺模型是「AI 为主、人为辅」范式升级关键——2D 侧已有 `auto2dlabel/tools/train_kitti.py` 先例（KITTI 微调 YOLO 提精度）；3D 侧 mmdet3d 微调域内再训练是自然延伸
- **范围**：
  - mmdet3d 训练管线：config 改造（数据集路径/类表/轮数）+ 标注数据组织（KITTI label 直喂 / nuScenes devkit 格式）+ 训练脚本（复用 v0.2 环境，spconv 已编译）
  - 微调后同口径评测对比（官方权重 vs 微调权重：KITTI moderate / nuScenes mAP）
  - 权重管理：微调权重落 `weights/` 不入库（红线不变）
- **验收**：任一引擎（pvrcnn_kitti / centerpoint_nus 首选）微调后同口径出表，对比官方权重如实记录（提升/持平/退化）
- **成本**：最高（训练管线 + GPU 时间 + 数据组织）；预算不足时降级「仅训练管线就绪 + 小样本冒烟」

## Stop（v0.4 不做，如实记录）

- **不再扩展模型矩阵**：9 引擎已覆盖 LiDAR/单目/融合 × KITTI/nuScenes × 精度/速度档；VoxelNeXt（全稀疏 64ms/帧）/ SparseDrive 留 v2+
- **KITTI 融合增强（后融合原型）**：官方无融合权重（v0.3 P3 如实记录），自写后融合成本高、预期收益低——v2+ 候选
- **LabelAny3D 重试**：判据实测不达标（yaw 中位差 44.2° 歧义 + 深度对齐 ~3m 误差已归因），换 matcher 前不复测
- **多 agent 框架**：auto2dlabel v0.6 已论证不引入，3D 侧不重复
