# Auto3dLabel v0.4 里程碑定义

> v0.4 = **HITL 编辑闭环补齐（P1 手柄编辑，最高优先）** + nuScenes 端到端标注闭环（P2）+ 训练→微调闭环（P3，v1.0 方向，成本高可延后）+ 地图矢量对账（P4，2026-09-15 追加回填）。
> 立项 2026-08-31（v0.3 收尾评估：3D 核心闭环已完整，剩余为增量项——用户采纳评估建议，三项候选入 v0.4）。**P4 为周期外增量交付后回填**（commit `3c44c2e`，立项时未列入）。

## 背景与决策

v0.3 收尾（2026-08-31）后现状：检测模型矩阵 9 引擎（LiDAR 5 + 单目 2 + 融合 2，KITTI/nuScenes 双数据集）+ HITL 三档分流 + Web 真 3D 四视图复核 + Agentic 闭环 + 多格式导出——**核心闭环完整，无「必须马上做」项**。v0.4 沿价值栈补齐三块增量：

1. **P1（推荐优先）**：P4b 手柄编辑——v0.3 明确记录「可选未做」的唯一规划项；补齐后「AI 初稿 → 人工修正」数据回路在 3D 侧真正完整（当前人工只能改标签、不能改 cuboid 几何）
2. **P2**：nuScenes 端到端标注闭环——BEVFusion / centerpoint / fcos3d 目前只评测出表，「测了不能用」；nuScenes pcd Web 复核无解析器（v0.1 记缺口至今未补）
3. **P3**：训练→微调闭环——标注数据反哺模型（auto2dlabel 侧 `tools/train_kitti.py` 先例），mmdet3d 微调域内再训练；成本最高，可延后

（P4 地图矢量对账为周期外增量，见文末 Phase 4 段；其立项背景 = MapTR 系矢量预测此前只评测无对账口径、无人工复核入口。）

## Phase 1：P4b cuboid 手柄编辑（Web 3D 复核补齐）

- **定位**：v0.3 P4a 已交付只读四视图 + 选中/改标签/删除/保存回写；**cuboid 几何编辑缺失**——AI 初稿框不准时人工无法修正尺寸/位置/yaw，只能改标签或重跑引擎
- **范围**（纯前端，three.js 已就位，不占 GPU）：
  - **cuboid 六面拖拽手柄**：六面中心手柄拖拽改对应面、角点吸附 raycast 模板（CVAT 借鉴）；编辑数学照 `resize/rotate` 既有模式（手柄相对 mousedown 快照，绝不增量累积）
  - **编辑对象**：尺寸 h/w/l、位置 xyz、yaw（BEV 平面旋转）——内部数据模型 `{position, size, yaw}` 不变
  - **保存回写**：Box3D `to_dict` 穿透点纪律（v0.1 红线，新增编辑路径不得绕过）；`*_reviewed.json` 协议扩展或原地覆盖（照 2D 协议）
  - **撤销/重做**：沿用 undo/redo 闭包栈模式（MAX 32，快照深拷贝）
- **验收**：
  - Web 打开 KITTI 帧 → 拖拽手柄修改 cuboid（尺寸/位置/yaw）→ 保存 → 导出 label 校验（15 字段 h/w/l/x/y/z/ry 与编辑一致）
  - jsdom 冒烟覆盖手柄数学（照 `smoke_web.js` 模式：mousedown 快照、六面拖拽、yaw 旋转、undo/redo）
  - 与 2D Web 复核（:8765）同端口共存回归（test_web3d 全绿）
- **成本**：1000+ 行 JS（v0.3 评估最重前端单块）；不做 raycast 模板吸附可降级为六面手柄 MVP

### Phase 1 验收回填（2026-08-31 ✅）

- **交付**：logic3d.js 编辑层（boxToCorners / yaw↔rotation_y 转换 / 2D 母版 resize 适配 + 增量式 yaw 旋转 + Side 一维编辑 / 状态机 + undo 闭包栈 MAX 32）+ viewer3d.js 手柄层（Top 4 角 + 4 边 + yaw 球、Side 顶/底/前/后，投影命中 <14px，中心平面射线求交拖拽，编辑中禁用视图旋转、实时几何刷新、相机锁定）+ index.html 编辑 hint。**后端零改动**（编辑体操作队列 JSON annotations[i]，buildSaveBody 全量直通）
- **验收对照**：六面手柄覆盖 ✓（Top BEV 面 + Side 立面六面）；尺寸/位置/yaw 全可编辑 ✓（w/l/位置 Top、h/cy Side、l/cz Side、yaw Top 球）；保存回写 + 导出走既有链路 ✓（编辑后 save → server 3D from_dict → labels/ 导出，穿透点纪律保持）；jsdom 冒烟 ✓（smoke_web3d.js 94 断言，编辑层 33）；同端口共存回归 ✓（pytest 双环境全绿，后端零改动）
- **MVP 降级如实记录**：raycast 模板吸附、Front/透视视图手柄不实现（覆盖重复）；undo 不覆盖删除/改标签（P4a 现状保持）；容器无浏览器可自动化 → 拖拽 E2E 手动验收待用户（数学/状态机/undo 由 smoke 断言兜底）
- **过程修正两处**：`edited_by_human` 置位时机（endEdit 几何容差判定，零变化不假标记、浮点往返噪声清理由 snapshot 恢复）；P4a 遗留 click 拦截失效修复（suppressClickUntil 时间戳）
- 实测数据见 `tests/test-v0.4.md`；质量门四件套全绿（pytest 1056/4 + 1059/1、ruff 0/75、mypy 0/167、pyright 0）

## Phase 2：nuScenes 端到端标注闭环

- **定位**：BEVFusion（mAP 27.0）/ centerpoint（23.4）/ fcos3d 均为评测出表，无标注闭环——nuScenes sample 无法 Web 复核、无训练格式导出，「融合/单目引擎主推但不可用」是价值兑现缺口
- **范围**：
  - **nuScenes pcd 解析渲染**：Web 复核第 6 相机 + LIDAR_TOP 点云（pcd 无解析器为 v0.1 记缺口；复用 `data/nuscenes.py` devkit 表 + `build_bevfusion_data` 标定链）
  - **复核队列协议扩展**：review 文件加 nuScenes sample 语义（scene/sample token 定位，非 frame_id）
  - **nuScenes 训练标签导出**：devkit 格式（bbox + 全局四元数 + 类别表），与 `export/` 现有 KITTI 导出并列
- **验收**：Web 复核 nuScenes sample（点云 + 6 相机 + 3D bbox 四视图）→ 改标签/保存 → devkit 可读标签导出 → 回灌评测口径可解析
- **成本**：中等（pcd 解析 + 前端相机视图 + 导出器）；nuScenes Web 复核无现成解析器，前端工作量同 P1 量级

### Phase 2 验收回填（2026-09-02 ✅）

- **交付**：cam_like 转换（`tools/geometry.py` 唯一落点，M @ (p−t_ego)，yaw_bev=−yaw_g，(h,w,l) 换序，velocity/track_id 透传）+ `data/nuscenes.py`（pcd 解析 6 相机 ego）+ `export/nuscenes_queue.py`/`nuscenes_labels.py`（NusBox↔渲染 dict 往返 + devkit 格式）+ `tools/nuscenes_pipeline.py`（三引擎协议分派：detect_points / detect_sample 4 参 bevfusion / 3 参 fcos3d）+ `models/detection3d.py` `create_detector3d_any` 统一工厂 + Web 三文件 nus 分支（payloads/server/app.js 仅 renderDetail 加 cameras）+ cli `nuscenes-queue` + smoke_nuscenes 回灌参数
- **验收对照**：E2E 实跑——bevfusion_nus 队列 **81 文件 / 2696 框** → Web 复核（点云 + 6 相机）批量保存 **2185 保留 / 464 删除** → labels 81 文件 NusBox 格式 → 回灌（labels 当 pred vs 官方 GT，零检测器加载 0.1s）出表 **mAP 24.6**（2226 框 × 10 类）——闭环验收达成
- **如实记录**：回灌 mAP 24.6 < 官方 BEVFusion 27.0（人工删除低 conf 框 + 简化口径差异）；闭环验收点 = 「训练标签可解析回灌出表」，非 AP 提升
- 实测数据见 `tests/test-v0.4.md` Phase 2 段

## Phase 3：训练→微调闭环（v1.0 方向，成本高可延后）

- **定位**：标注数据反哺模型是「AI 为主、人为辅」范式升级关键——2D 侧已有 `auto2dlabel/tools/train_kitti.py` 先例（KITTI 微调 YOLO 提精度）；3D 侧 mmdet3d 微调域内再训练是自然延伸
- **范围**：
  - mmdet3d 训练管线：config 改造（数据集路径/类表/轮数）+ 标注数据组织（KITTI label 直喂 / nuScenes devkit 格式）+ 训练脚本（复用 v0.2 环境，spconv 已编译）
  - 微调后同口径评测对比（官方权重 vs 微调权重：KITTI moderate / nuScenes mAP）
  - 权重管理：微调权重落 `weights/` 不入库（红线不变）
- **验收**：任一引擎（pvrcnn_kitti / centerpoint_nus 首选）微调后同口径出表，对比官方权重如实记录（提升/持平/退化）
- **成本**：最高（训练管线 + GPU 时间 + 数据组织）；预算不足时降级「仅训练管线就绪 + 小样本冒烟」

### Phase 3 验收回填（2026-09-02 ✅）

- **交付**：`tools/train3d.py` 五步管线（ImageSets → create_data 幂等 → subsample_infos 确定性截取保 metainfo → build_finetune_config 官方 config 对象级改造 → 训练 subprocess cwd=.mim/tools）+ `smoke_kitti` [config] [checkpoint] 参数（Mmdet3dDetector 直构，detect_points 协议复用）
- **关键改造**：GT-AUG 全关（db_sampler + ObjectSample，嵌套 pipeline 双赋值）、data_root/ann_file/load_from 全绝对化、param_scheduler 纯 iter-based LinearLR 预热 + ConstantLR（官方 T_max 绑 epoch_num 教训）、lr 0.0003、batch 2、epoch 4、官方权重热启
- **验收对照**：冒烟训练（300/40 帧，epoch 4 × RepeatDataset 2 = 1200 iter，0.078s/iter，显存 1.7GB）exit 0——**反传探针过（loss 0.32→0.39 无 NaN）**；同口径评测 **40-point 主口径微调全面优于或持平官方**（Car hard 76.4→80.5、Ped moderate 19.7→22.4），11-point 口径 Car 略降 Ped 大涨——提升/退化如实记录见 `tests/test-v0.4.md` Phase 3 段
- **降级如实记录**：内置 KittiMetric val 关闭（numba 0.67 × CUDA 13 import 期编译失败，环境级；val_begin 越界关闭——mmengine 强制最终 epoch val）；评测由 smoke_kitti 自写 40-point 口径承担；微调引擎 = pointpillars_kitti（12GB 约束用户已确认，PV-RCNN 大概率 OOM 排除）
- 训练坑 5 个均有回归断言（train.py 平级路径 / 相对路径 resolve / convert_to_iter_based 断言 / Config 引用不传播 / val 关闭）

## Phase 4：地图矢量对账（MapTR 契约消费，2026-09-15 追加 ✅）

> **回填说明**：本 Phase 为 v0.4 周期外的增量交付（2026-09-15 commit `3c44c2e`），立项时未列入 v0.4 定义；因同属「3D 侧 HITL 复核 + 对账」价值栈，回填于此并如实标注归属。

- **定位**：MapTR 系矢量地图预测（车道线/人行横道/路沿/中心线）此前无对账口径——预测结果无法与 GT 定量比对、无人工复核入口。本 Phase 交付**消费侧**：吃产出方逐帧契约 → 自动比对 → 报告 + 复核队列。
- **契约与依赖红线**：`mapvec_pred/1`（`schema` 字段不匹配即拒收；`coord=ego`，x 前/y 左，原点 ego 后轴中心，米；`bev_range=[-15,-30,15,30]`；`preds`/`gts` 实例数组 `{class, points: [[x,y]×20], score?}`，类序 `MAPTR_CLASSES`）。**纯值逻辑复制自 `AutoDriveData/autodrivedata`（mapvec_schema / chamfer_ap / mapviz + geometry），不 import**——依赖单向红线（AutoLabel 不反向依赖 AutoDriveData）；产出方改契约须同步复制，**交叉验证测试锁定一致性**（`test_mapvec_crosscheck.py` 逐函数比对原实现）。**越窗不算错误**：GT 恒在窗口内、pred 无裁剪（实测 x 达 19.75）→ 只计数 `out_of_window` 供诊断，不拒收。
- **交付**（4 模块 + 4 测试文件）：
  - `schema/mapvec.py`：契约 dataclass + `frame_from_dict` 硬校验（字段/几何/类名）
  - `schema/mapvec_proj.py`：ego 折线 → 相机像素 + BEV 面板投影链（ego → CARLA 世界 → `world_to_cam`）；**旋转单位弧度**（历史坑：度数值直传会让 6 相机中只有 yaw≈0 的 CAM_FRONT 恰好接近正确；第一版只投 CAM_FRONT 天然避坑，多相机走 `cam_pose` + 锚点单测）
  - `tools/mapvec_compare.py`：`chamfer_distance` / `chamfer_cost_matrix` / `match_greedy`（逐类贪婪一对一，近者先占位、GT 不重复使用）/ `compare_frame` / `aggregate`
  - `export/mapvec_report.py`：CLI 主流程（校验 → 比对 → 渲染 → 报告 → 复核队列）
  - 前端：`web/static/logic3d.js` + `app.js` 支持 overlay/BEV 图展示，`smoke_web3d.js` 扩展
- **比对口径（与产出方官方评估同口径）**：TP/FP/FN 用 CD ≤ **0.5m** 判定；**AP = 三阈值 {0.5, 1.0, 1.5}m 的 precision 均值，无 recall 项**——故报告强制打印 `score_thr`（绝对数字必须带阈值引用）；逐帧先匹配再计数、全局再聚（对齐官方跨帧汇聚，GT/pred 不对称帧不引入偏差）。
- **产物**：`overlay/{token}_overlay.png`（CAM_FRONT，pred 品红 / GT 青绿）+ `{token}_bev.png` + `mapvec_report.md`（逐类 TP/FP/FN/AP + CD 中位/p25/p75 + 最差 5 帧）+ `mapvec_report.json`（逐帧）+ 复核队列 `{token}_review.json`（`REVIEW3D_DIR` 指向后 `/api/review-files` 直接可见，`review-save` 无副作用）
- **验收对照**（实测，`outputs/mapvec_report/` 与 `outputs/mapvec_report_600/`）：

  | 运行 | 帧数 | CD 中位（匹配对） | divider | ped_crossing | boundary | centerline |
  | --- | --- | --- | --- | --- | --- | --- |
  | `maptr_ep512.pt` | 100 | 0.37m（418 对） | TP 65 / FP 2915 / FN 1364 / AP 0.054 | 0 / 377 / 118 / 0.006 | 162 / 3299 / 1626 / 0.076 | 191 / 4499 / 3634 / 0.132 |
  | `maptr_600.pt` | 100 | 0.39m（683 对） | 127 / 3880 / 2347 / 0.156 | 0 / 982 / 175 / 0.024 | 206 / 4409 / 2706 / 0.189 | 350 / 4639 / 5348 / 0.274 |

  两轮均产出 100 个 overlay + 100 个 BEV 图 + 100 个复核队列文件；`maptr_600` 全类 AP 优于 `ep512`（centerline 0.132→0.274）——对账口径可区分模型版本，链路有效。
- **如实记录**：① 绝对 AP 低（0.006–0.274）源于 **precision 口径无 recall 项 + 未按 score 做全局排序裁剪**，与官方 chamfer_ap 同口径，**不与常规 mAP 横向比较**；② ped_crossing 两轮 TP 均 0（预测侧该类几乎未命中 0.5m 阈值），是模型/阈值现象非链路问题；③ 多相机投影未实现（只投 CAM_FRONT，见上旋转单位坑）；④ 契约消费侧**无写入能力**——复核队列 `annotations` 为空、`review-save` 无副作用（只读对账，矢量编辑留后续）。
- **测试**：`test_mapvec_schema.py`（5）/ `test_mapvec_proj.py`（8）/ `test_mapvec_compare.py`（7）/ `test_mapvec_crosscheck.py`（5，与原实现逐函数交叉验证）共 **25 用例**；`smoke_web3d.js` 扩至 103 断言。pyright 侧 3 条存量告警即出自 `test_mapvec_crosscheck.py`（`autodrivedata` 可选依赖不可解析，属依赖单向红线的预期代价）。

## Stop（v0.4 不做，如实记录）

- **不再扩展模型矩阵**：9 引擎已覆盖 LiDAR/单目/融合 × KITTI/nuScenes × 精度/速度档；VoxelNeXt（全稀疏 64ms/帧）/ SparseDrive 留 v2+
- **KITTI 融合增强（后融合原型）**：官方无融合权重（v0.3 P3 如实记录），自写后融合成本高、预期收益低——v2+ 候选
- **LabelAny3D 重试**：判据实测不达标（yaw 中位差 44.2° 歧义 + 深度对齐 ~3m 误差已归因），换 matcher 前不复测
- **多 agent 框架**：auto2dlabel v0.6 已论证不引入，3D 侧不重复
